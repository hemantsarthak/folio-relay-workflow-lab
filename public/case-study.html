01 / FRONTEND ENGINEERING

Folio: getting a packet ready for review

A missing document creates a sequence of work: identify the gap, ask the right client, receive a replacement, inspect evidence, and record a human decision. Folio keeps that sequence separate for every client and tax year.

Try FolioInspect the code

Try this sequence

  1. Choose Alex. The checklist shows a missing W-2 and an open K-1 request. The K-1 source on file is from 2024, while the request expects 2025.
  2. Follow the step guide at the top: issue the 2025 K-1 request as the preparer, then press Answer as Alex to switch to the client’s portal.
  3. Use the synthetic sample. Folio returns you to the preparer view with the routing suggestion and year excerpt. Record a review note and close the request; the checklist marks the K-1 verified.
  4. Request the missing W-2 from the checklist and repeat the loop, this time with Jev live selected in the sidebar if you have a reviewer code.
  5. Choose Morgan. The reviewed 1099 is ready for preparer handoff. Edit the profile's tax year to 2026: the 2025 evidence becomes insufficient for that year.
Engineering decisions and boundaries

State and evidence

Typed transitions govern requests. Wrong-year and ambiguous responses stay open. Readiness derives from reviewed current-year questions, and extra open requests still block handoff. Duplicate open requests for the same client, type, and year are rejected.

Useful failure handling

PDF parsing happens in the browser. Scanned or unreadable documents need attention. Live provider failures stay visible. Exports omit raw document text. Browser persistence is per device; the role preview has no production authentication.

02 / IT ENGINEERING

Relay: owning the follow-through

IT support needs a person, an asset or account, evidence, and a next step. Relay connects those records with an employee help portal, a support queue, a directory, an offboarding audit, and an operations worklist.

Try RelayInspect the code

Try this sequence

  1. Open the Help portal as Maya, choose “Remote desktop, VPN or Wi-Fi”, tick “Colleagues have the same problem” and send it. Jev or local rules route it immediately; open the Support queue to see it as IT, then assign an owner and watch the portal progress update.
  2. Choose Jordan in People & access, then audit the directory snapshot. The active Slack account and assigned laptop create two offboarding findings.
  3. Back in People & access, record disabled access and returned hardware with operator notes. Audit a fresh snapshot to see the changed local result.
  4. Open Operations review and load the shared-session drill. Two additional tax-team reports form a repeated Remote desktop pattern.
  5. Open one ticket, record an owner and an investigation plan, then resolve it. Return to Operations review to see the open work and pattern update.
Engineering decisions and boundaries

Traceable operations

Access and device changes require operator notes. The CSV audit reconciles normalized source exports. Employee-created tickets use stable directory IDs. Ticket work plans feed the operations summary and export.

Careful automation

The PowerShell collector reads local diagnostic observations. Runbooks guide an operator. Repeated reports are a signal to investigate shared services. Identity, device, and account changes are simulated; actual administration needs authorized integrations.
