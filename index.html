02 · How Jev fits

A model answers a narrow question. Code decides what happens.

Jev is a structured-decision model from TypeSafe, called here through OpenCode Zen. Instead of asking it to “handle” a document or ticket, the server asks two typed questions and gets back probabilities it can check.

  1. The browser sends plain textFolio extracts PDF text locally; Relay sends the ticket title and description. POST /api/classify with kind, text and mode.
  2. The server asks two questionsA choice question (which category, from a fixed list with written criteria) and a noul question (does this need a person’s attention now?). Content is treated as data, not instructions.
  3. The answer is validatedUnknown labels, out-of-range scores or probabilities that don’t sum to 1 are rejected with a visible error. Nothing is applied. Live mode never silently falls back to rules.
  4. Code and people take it from thereFolio compares the tax year in code; Relay picks a runbook. A preparer or IT admin confirms, overrides, and closes. Every step lands in an audit trail.
server/decisions.mjsrequest → answer

Request (key stays on the server)

{
  "model": "jev-1.13-free",
  "state": { "content": "Schedule K-1 … Tax year: 2024" },
  "questions": {
    "category": {
      "type": "choice",
      "criteria": {
        "W-2": "…", "1099": "…", "K-1": "…",
        "Receipt": "…", "Other": "…"
      }
    },
    "attention": {
      "type": "noul",
      "instructions": "Missing or conflicting info?"
    }
  }
}

Answer (checked before use)

{
  "answers": {
    "category":  { "choice": "K-1", "confidence": 0.93,
                   "probabilities": { "K-1": 0.93, "Other": 0.04, … } },
    "attention": { "noul": 0.12 }
  }
}
// Illustrative values. The tax year (2024 ≠ 2025)

04 · Questions

Worth knowing before you click.

What is “Reviewer live access”?

The public site routes with local rules so it costs nothing to run. If Hemant sent you a reviewer code, open either app, expand “Have a reviewer code? Unlock live Jev”, enter it, then choose Jev live as the routing engine in the sidebar. The code is a quota gate for the shared API key, not a login.

Is any of this real data?

No. Every client, employee and document is synthetic. Records save in your browser only, and each app has a reset.

Does it send emails, Slack messages or change accounts?

No. Requests, account changes and device returns are simulated records with operator notes. Real use would need authentication, durable storage and authorised integrations.

What’s the stack?

React 19, TypeScript, TanStack Query, Vite, PDF.js and lucide-react on the front end; Express locally and a Netlify function in production for the Jev adapter; a PowerShell collector for Windows diagnostics; Node’s test runner for 32 tests.

Was it built with AI help?

Yes, with AI assistance. The design choices — typed transitions, validated model answers, visible failure and human sign-off — are what I’d want to discuss.

Is this affiliated with Rivet?

No. These are independent concepts inspired by Rivet’s open roles. The visual style nods to rivet.tax; no Rivet code, data or branding assets are used.
